# HealthHub v0.6.0, Food Library & Spreadsheet Import

HealthHub v0.6 extends the existing `foods` catalogue rather than introducing a parallel database. Food records remain shared between profiles, while recent use, frequency, favourites and default quantities are stored in `food_preferences` per profile.

## Spreadsheet workflow

Open Foods → Import Foods, copy the visible template or paste TSV cells from Excel, Google Sheets or Numbers, then choose Preview import. Headers may be in any order and common aliases such as `Food`, `Product`, `kcal`, `Protein (g)`, `Carbohydrates` and `Sodium mg` are recognised. `name` is required. Serving size, serving unit and nutrition fields may be incomplete, but invalid numeric values and negative values are reported before save.

Preview never writes records. Valid rows can be committed with duplicate handling. Potential duplicates use name, brand, serving size and serving unit. Each commit records a batch and per-row action for later audit and future undo support.

## Data quality

`data_quality` distinguishes `packaging_confirmed`, `user_entered`, `estimated`, `imported` and `foodhub_derived`. Estimated records remain editable and are not presented as verified packaging data.

## Composite foods

Composite foods use component HealthHub food records and quantities. Nutrition is calculated at creation time from the components, so the diary logs the composite with one action. Future releases can add recalculation/versioning when component definitions change.

## FoodHub boundary

FoodHub remains responsible for recipes, meal planning and recipe ingredients. HealthHub continues to communicate only through the versioned adapter. The shared food model and stable IDs provide the future mapping point for authoritative FoodHub recipe nutrition without sharing databases.
